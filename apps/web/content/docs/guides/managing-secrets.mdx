---
title: Managing secrets
description: Create and reference encrypted secrets in monitors.
---

## Create a secret

1. Open **Secrets** → **Create**.
2. Enter an **alias** (reference name used in monitors).
3. Paste the **value** (token, password, API key).
4. Save — the value is encrypted and cannot be viewed again.

## Test a secret

Use **Test** on a secret to verify it decrypts correctly before referencing it in monitors.

## Reference in monitors

In a monitor step, reference secrets by alias — for example, in an `Authorization` header or request body field. Rythm injects the value at execution time and **masks** it in run output.

## Rotate a secret

1. Edit the secret and provide a new value.
2. Re-run affected monitors to confirm auth still works.
3. Revoke the old credential at the upstream system when rotation is complete.

<Callout type="warn">
  You cannot retrieve a secret’s value after save. Store credentials in your team’s vault as the source of truth.
</Callout>

See [Secrets and certificates](/docs/concepts/secrets-and-certificates).
